# CiteMind 项目说明与使用手册

证据 AI 知识库 · v1.1 · 2026年10月18日

## 1 项目概览

CiteMind 是面向个人资料的浏览器端知识检索应用。导入笔记、项目文档或带文字层的 PDF 后，用户可以围绕资料提问，阅读相关原句，并通过引用核对来源。本手册说明本地启动、实际功能、数据保存、实现方式和简历展示方法。

### 当前版本能做什么

| 功能 | 使用结果 |
| --- | --- |
| 资料导入 | 支持 PDF、TXT、Markdown、粘贴文字，内置 5 篇中文示例资料。 |
| 两种检索 | 快速模式按词语相关度检索；本地 AI 模式使用中文句向量，支持语义相近的表达。 |
| 引用核对 | 返回原文摘录与编号引用；PDF 来源保留物理页码，可切换文字页并核对高亮。 |
| 保存与迁移 | 可选保存在当前浏览器，支持 JSON 知识库备份、合并或替换恢复。 |
| 问答导出 | 将当前问答、模式、检索耗时和来源导出为 Markdown。 |

### 准确理解 AI 的作用

AI 部分把问题和资料转换为向量，用于寻找意思相近的内容。回答直接摘录检索到的原文；当前没有接入生成式大语言模型，不提供跨资料的生成式总结或自由对话。可以将本项目定位为生成式 RAG 可使用的检索与证据层。

资料相关性不足时，应用提示资料不足。排序分数只表示检索相关度，不能解释成事实正确概率。原文自身可能有错误，最终判断仍需核对来源。示例知识库是虚构产品资料，用于展示功能。

### 当前交付与访问状态

完整源码包可通过 Windows 启动入口在本机运行；静态部署包用于更换托管平台。原 chatgpt.site 地址已被用户浏览器和此前检查确认遭到 Cloudflare 拦截，暂不能用作有效的简历演示链接。新的公开入口应完成真实访问验证后再填写。

项目不要求 API Key。首次使用 PDF 或本地 AI 仍需下载公共组件和模型；当前不承诺首次离线可用。

## 2 启动应用与首次体验

建议先在本地完成一次完整演示，再部署公开入口。快速检索无需下载模型，适合先确认导入、提问和引用功能。

### Windows 启动步骤

1. 安装 Python 3，并完整解压 CiteMind v1.1 源码包。不要直接在压缩包内运行。
2. 双击“启动应用.cmd”。脚本启动本机静态服务，并在浏览器打开应用。
3. 默认地址为 http://127.0.0.1:4173。端口被占用时依次尝试 4174 至 4182；以服务窗口显示的地址为准。
4. 体验过程中保持服务窗口打开。关闭该窗口即可停止本机服务。

若自动打开浏览器失败，可手动打开服务窗口显示的地址。页面使用 ES Modules 和独立 Worker，需要通过 HTTP 或 HTTPS 访问，直接双击 index.html 打开的 file 地址不适用。

### 备用启动方式

在源码项目目录打开终端，运行下面的命令；无需安装前端构建工具。Python 只提供静态文件，不承担资料解析或模型推理。

```text
python tools/serve.py --no-browser
```

也可使用 Python 标准库，明确指定 dist 为站点目录：

```text
python -m http.server --bind 127.0.0.1 4173 --directory dist
```

### 五分钟演示顺序

| 时间 | 操作与展示重点 |
| --- | --- |
| 第 1 分钟 | 使用示例资料提问“这个知识库如何避免 AI 编造答案？”，打开一条引用。 |
| 第 2 分钟 | 导入自己的 TXT 或带文字层的 PDF，针对其中一个事实提问。 |
| 第 3 分钟 | 点击 PDF 来源，核对物理页码、提取文字及命中原句。 |
| 第 4 分钟 | 在“保存与备份”开启本机保存，导出 JSON，再刷新核对资料恢复。 |
| 第 5 分钟 | 导出问答记录；模型已就绪时展示语义改写问题，并测试一个无关问题。 |

首次模型下载可能超过演示时间。面试前先完成一次下载和预演，同时保留快速检索流程；不要把已缓存加载时间描述为首次访问速度。

## 3 资料导入提问与引用核对

左侧“选择文件”支持多文件选择和拖放；“或直接粘贴文本”可添加有标题的纯文本资料。资料加入后，输入问题并按 Enter 发送，Shift + Enter 换行。

| 输入项目 | 当前限制 |
| --- | --- |
| PDF | 单份不超过 10 MB、80 页，提取文字不超过 100,000 字符。 |
| PDF 类型 | 需要可提取的文字层。不支持扫描件 OCR、加密或受权限保护的 PDF。 |
| TXT 和 Markdown | 使用 UTF-8 编码；单文件不超过 1 MB，单篇不超过 100,000 字符。 |
| 知识库总量 | 最多 20 篇资料，原文合计不超过 250,000 字符。 |
| 输入问题 | 单次最多 1,000 字符；当前对话最多 20 轮，达到后先导出记录，再新建对话。 |
| JSON 备份 | 单份不超过 6 MB，恢复时再次校验文档和 PDF 页码信息。 |

### 如何提问更容易核对

围绕资料中可验证的事实提问，例如“单份 PDF 支持多少页”“开启保存后资料在哪里”“项目如何处理没有证据的问题”。本地 AI 模式可尝试改写为“我的资料会不会被传走”，观察是否返回对应隐私原句。结果以实际资料为准。

右上角“快速检索”可切换到“本地 AI 语义检索”。首次启用显示下载进度，可取消、重试。加载失败时，快速检索仍可使用；本地 AI 不会自动变成远程模型调用。

### 如何阅读引用

回答的编号对应来源卡片。点击来源后，核对资料标题与高亮原句。PDF 显示提取文字和物理页码，不展示原 PDF 页面图像。物理第 3 页可能与文档印刷页码不同，应以原文件的页面顺序核对。

PDF 保留空白页信息，分块不跨页。可以切换指定页或查看全部提取文字。复杂表格、多栏排版和公式可能出现阅读顺序或提取偏差，重要内容应回到原 PDF 确认。没有文字层的扫描件需先用其他工具做 OCR。

### 问答记录与无关问题

每次检索显示本次实际耗时。回答下方可复制带来源的内容或“导出记录”，保存为 Markdown。对资料外的问题，例如“明天杭州会下雨吗”，应看到资料不足提示；这不等于应用具备实时天气查询能力。

## 4 本机保存备份与隐私

“保存与备份”用于管理知识库文字。“导出记录”用于保存问答。两类导出包含的内容不同，迁移设备前应分别检查。

| 方式 | 包含的内容 | 不包含的内容 |
| --- | --- | --- |
| 当前页面内存 | 文档、检索索引及当前问答；只在本次页面会话使用。 | 刷新后的持续保存或跨设备同步。 |
| 浏览器本机保存 | 当前知识库文字、文档信息与 PDF 分页元数据。 | 原始 PDF、聊天记录、模型向量。 |
| JSON 知识库备份 | 文档标识、标题、原文、PDF 页码与位置。 | 原始 PDF、聊天记录、模型向量。 |
| Markdown 问答导出 | 当前问答、检索模式、耗时、来源与原文摘录。 | 可直接恢复的完整知识库。 |

### 开启和关闭本机保存

本机保存默认关闭，此时刷新会恢复示例资料。打开“保存与备份”，开启“保存在此浏览器”，等待状态显示保存完成后再刷新。开启后，资料写入 IndexedDB；同一浏览器访问同一站点地址时可恢复。

关闭本机保存会移除浏览器中的资料副本，当前页面仍可继续使用资料。清除站点数据、使用无痕窗口、更换浏览器、端口、域名或设备，都可能无法读取原有资料。更换部署地址之前应先导出 JSON。

### 导出和恢复知识库

1. 点击“导出知识库”，保留下载的 JSON；文件含资料原文，应与原始文件一起妥善保存。
2. 恢复时先选择导入方式，再点击“导入备份”。“合并到当前资料”保留现有内容，按标题、原文和类型去重；冲突的文档标识会重建。
3. “替换当前资料”使用备份覆盖当前知识库，并清空旧对话。合并新增资料也会重建索引并清空当前对话，操作前可先导出问答。
4. 备份格式、范围或分页信息无效时应拒绝恢复；不要把失败提示理解为已经覆盖成功。

### 哪些数据会发生网络请求

文档解析、检索和向量计算在浏览器中完成，应用不把资料或问题发送到应用服务器或远程推理接口。首次 PDF 导入与本地 AI 启用会访问公共 CDN、Hugging Face 下载组件或模型，这些服务可能收到常规网络请求。托管服务也可能记录普通访问日志。

模型文件可能被浏览器缓存，资料向量仅保留在页面内存。模型缓存、JSON 备份和本机知识库是不同的数据；缓存被清理后可能需要重新下载模型。

## 5 技术结构与检索过程

应用由静态页面和浏览器内计算组成。公开部署不需要业务后端数据库，Python 只用于本机提供静态文件。

| 模块 | 职责 |
| --- | --- |
| app.js | 导入、提问、引用面板、模型状态、本机保存与导出交互。 |
| engine.js | 资料分块、词语检索、语义召回、句级重排与原文位置。 |
| model.js | 独立 Worker 中加载模型、批量推理、排队、取消与超时重试。 |
| pdf.js | 加载 PDF.js，提取文字并保留连续物理页码与位置。 |
| storage.js | IndexedDB 读写、备份序列化、输入校验及恢复。 |

### 从资料到证据

1. 分块：按句段边界切为最多 420 字符的块，相邻块保留 64 字符重叠；PDF 页边界优先，不跨页切块。
2. 快速检索：结合中文分词、汉字片段与英文技术词，参考 BM25 的词频、稀有度、块长度和标题匹配排序，再选择相关原句。
3. 语义召回：将问题和资料块转换为向量，按余弦相似度召回候选块，并复用内存中的向量。
4. 句级重排：继续嵌入候选原句，按与问题的语义接近程度重新排序，词语匹配只作补充。
5. 返回引用：输出原句、文档标识、分块标识、原文位置和可选 PDF 页码；界面按文本展示内容并高亮出处。

### 本地 AI 的实际配置

使用 Transformers.js 3.8.1 和 ONNX Runtime / WASM，模型为 Xenova/bge-small-zh-v1.5。q8 权重约 24 MB，另需分词器和 WASM 组件；使用 CLS 池化，得到 512 维归一化向量。首次下载体积和初始化开销不等于单次检索耗时。

模型加载和推理放入 Web Worker，减少计算对页面输入及滚动的影响。小批量排队、缓存、加载进度、取消和超时重试用于管理等待与错误。当前采用内存检索，资料规模超过现有上限时需要重新评估索引方案。

### 引用为什么能对应原文

PDF 分页元数据保存 pageNumber、text、start、end，页码从 1 连续递增并保留空白页。引用使用 JavaScript UTF-16 索引指向原文，避免清理或裁剪文字导致位置错位。用户内容通过文本节点显示，不作为 HTML 执行。

## 7 部署要求与常见问题

可将 dist 目录中的文件部署到支持 HTTPS 的静态托管服务。入口文件应在站点根目录，ES Modules 和 Worker 应以正确类型加载。应用可加载与本地 AI 资源能下载，需要分别验证。

### 网络依赖和迁移检查

PDF.js 使用固定版本 6.4.299，运行组件和 AI 依赖也使用固定版本或模型修订。浏览器需访问公共 CDN 与 Hugging Face。当前部署包没有把全部模型和运行组件随站点打包，首次下载受用户网络影响；缓存存在也不等于完整离线支持。

迁移时保持文件相对路径，发布完整 dist 内容。更换域名或端口前先导出知识库与问答；新地址与旧地址的浏览器存储互不共享。验证页面、脚本、PDF、AI 模型及保存恢复后，再把公开入口加入简历。

### 遇到问题时按现象检查

| 现象 | 处理方式 |
| --- | --- |
| 启动窗口一闪而过 | 确认 Python 3 可运行、源码已完整解压，再在项目目录执行备用启动命令查看提示。 |
| 页面空白或模块报错 | 使用本机服务给出的 HTTP 地址；确认静态托管的 JS 文件路径和类型正确。 |
| 模型一直加载或失败 | 检查公共资源网络访问，取消后重试；可继续使用快速检索。不要把本地资料上传当作解决办法。 |
| PDF 组件加载失败 | 首次使用需要公共 CDN；检查网络后重试。文本导入与快速检索可先使用。 |
| PDF 提取为空或顺序异常 | 检查是否为扫描件或复杂分栏；先做 OCR 或转为 UTF-8 文本，并回原 PDF 核对。 |
| 刷新后资料或对话消失 | 资料需显式开启本机保存并等待完成。聊天记录不持久化，应另外导出 Markdown。 |
| 备份导入失败 | 检查 JSON 是否为本应用备份、大小不超 6 MB、总量未超限；保留原文件，不手工删改分页字段。 |
| 打开链接显示被拦截 | 记录错误页面、时间及 Ray ID，核对托管访问设置或更换合法托管入口；应用界面改动不能消除平台拦截。 |

进一步开发可从扫描件 OCR、增量索引和人工标注评估集开始。加入生成式回答时，还需单独实现资料远程发送告知、服务端密钥保护和引用校验。
