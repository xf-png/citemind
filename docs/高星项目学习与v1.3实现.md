# 从检索问答到研究工作台

2026-11-05。CiteMind v1.3 围绕一条实际流程实现：选资料 → 找原文 → 收集证据 → 写个人笔记 → 对照多份资料 → 导出可核对的记录。

## 新增能力

1. **资料范围**：侧栏搜索名称，逐份勾选、全选或清空选择；问答与导出记录保留当次检索范围。
2. **证据笔记**：从问答或对照表收集原文，按精确来源位置去重。最多 100 条，每条可写 2,000 字批注，并手动标记待整理、支持、存疑 / 反例或背景。
3. **资料对照**：最多六个问题，分别在每份所选资料内快速检索，呈现“问题 × 资料”表格。保留未找到相关片段的空缺，不自动判定资料间的共识、矛盾或事实真伪。
4. **来源状态**：证据保留收集时的原文、标识、UTF-16 位置和可选 PDF 页码。原资料移除后仍保留笔记；正文或页码不一致时显示待核对，禁止跳到错误位置。
5. **完整备份**：研究笔记与资料放在同一个 IndexedDB 记录中提交；完整 JSON 备份包含两者，兼容没有笔记的旧 v1 备份。合并时重映射冲突的资料及片段标识，保留已有批注。
6. **可带走的成果**：分别导出研究笔记、资料对照和问答记录 Markdown，保留出处与待核对状态。Markdown 是阅读用记录，完整恢复仍使用 JSON。

“支持”“存疑”等标记来自用户；程序只核对摘录与当前资料是否一致。恶意或错误的导入内容不会因为通过格式校验就成为真实证据。

## 检索性能改进

原先每次提问都会重复对全部文本块分词、统计词频，并扫描每个块。本版建立词项到文本块的倒排表，只为有命中词的块计分；评分公式、阈值及排序一致。缓存用完整文本块内容和元数据作为键，避免正文、标题、页码或位置变化后复用旧引用。最多保留三个语料索引，键总量限制为 100 万 UTF-16 字符。

运行 `npm run benchmark` 可与仓库历史提交 `b002cf8` 的 v1.2 引擎比较。脚本先核对结果、排序、分数、摘录与位置，再计时。结果见 [本次测量](verification/retrieval-benchmark-2026-11-05.json)。这是合成语料的本机热索引实验，不能推导所有设备的提速、真实检索准确率或本地 AI 推理速度。

## 验证与范围

- 原有 24 项引擎与存储检查保留；新增研究数据检查覆盖范围隔离、语义模型输入、引用伪造、失效来源、备份兼容、ID 冲突和导出转义。
- 浏览器验证覆盖 8 条用户流程，各在桌面与 390px 移动视口执行，共 16 条。移动视口使用桌面 Chrome，不代表真机 Safari 或 Android 验证。
- 对照表使用所选语料的共享词频统计，为每份资料选取相关原句，并检查原句对已知问题词的覆盖。它不会展示跨资料分数或把“未找到”解释为不存在。相较普通问答，对照候选使用更低的块阈值，再以句子覆盖筛除宽泛命中；这些是启发式规则，不能替代人工标注评估。
- 没有新增生成式总结、OCR、云同步、远程模型接口或自动事实核查。本地 AI 组件沿用 v1.2，新增的资料筛选在调用模型前生效。
