# 把研究工作台留在设备上

2026-11-05，CiteMind v1.4。让已有的资料范围、证据笔记和资料对照在断网重开后仍可使用，PDF 与本地 AI 也包含在完整离线包中。

## 使用步骤

1. 通过 HTTPS 网站或本机静态服务打开 CiteMind，进入“保存与备份”。
2. 若需保留自己的资料和研究笔记，单独开启本机保存，并导出 JSON 备份。
3. 点击“准备完整离线包”，保持页面和网络连接，等待显示“已就绪”。完整包约 53 MB（50.5 MiB），含 258 项资源；速度取决于网络和设备。
4. 断网后使用同一浏览器、同一地址重新打开，即可继续检索、整理证据或导入新的文字层 PDF。使用 localhost 地址时仍需启动本机服务。
5. 联网时可检查更新。新版准备完会等待本站旧页面全部关闭，先保存工作，再关闭并重开。不会自动刷新当前页面。
6. “移除离线包”只移除本站路径范围的程序缓存和离线注册；资料、笔记及其他应用缓存保持原状态。

离线包默认不准备。没有准备完成、浏览器回收了缓存、换浏览器或清除了站点数据时，不能保证断网重开。程序缓存不替代资料备份；JSON 备份包含资料文字和笔记，不含 PDF 原文件。

## 从高星项目学到的设计

参考 [Workbox 项目](https://github.com/GoogleChrome/workbox)（本次查看约 13k stars），阅读官方的 [workbox-build](https://developer.chrome.com/docs/workbox/modules/workbox-build) 和 [Service Worker 更新处理](https://developer.chrome.com/docs/workbox/handling-service-worker-updates)，并结合 [MDN 的生命周期说明](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)。星数会变化。

采用预缓存清单、资源修订和浏览器更新生命周期的思路。CiteMind 用独立编写的原生 Service Worker 实现，没有引入 Workbox 代码或新增运行时依赖。完整清单由脚本根据实际部署文件生成，避免依赖手写的若干 URL 后误报完整离线。

## 具体实现

- 资源包含网页、模块、样式、图标、PDF CMap 与字体、固定版本的 Transformers.js / WASM 及 BGE 模型。清单记录每项的路径、字节数、SHA-256，并派生版本修订号。
- 首次准备四路并行下载，逐项校验完整响应，全部完成才写入就绪标记。资源不匹配、网络失败或空间不足时删除未完成的新版本，原已激活的版本继续工作。
- 升级优先读取旧版本缓存，再次检查 SHA-256，仅复用字节完全相同的文件。损坏或变化的文件重新下载，避免每次修改界面都重复下载约 47 MB 模型及运行组件。
- 缓存名包含本站路径，适用于 GitHub Pages 的 `/citemind/` 子目录。只拦截固定清单中的同源 GET，不缓存外站请求、未知地址或用户资料。
- 不调用 `skipWaiting()`，不强制重载。新版本安装完成后等待旧页面关闭；激活成功再清理本应用旧版本缓存。
- 就绪检查核对标记及清单内所有条目是否存在，发现缺失可重新准备。运行时不为每次读取重新计算大型模型哈希；字节校验发生在下载或复用时。
- 资料保存在 IndexedDB，离线程序在 Cache Storage，二者可以分别移除。第一次打开不会注册 Service Worker 或主动下载离线包。

这些是浏览器提供的离线存储机制，不是不可删除的永久备份。离线准备期间请保持页面打开；已安装版本的损坏缓存需要联网修复。

## 验证范围

自动化使用 Chrome / Chromium，桌面 1440×1000 与移动布局 390×844。移动布局仍运行于桌面浏览器，不代表真实 iOS 或 Android。浏览器共 32 条用例，其中真实模型推理仅桌面执行，合计 31 通过、1 跳过。

| 流程 | 实际验证 |
| --- | --- |
| 主动准备与断网重开 | 初始无离线注册；准备后断开网络并刷新，完成检索、收集证据、编辑笔记，再次刷新仍能恢复已保存笔记 |
| 真实本地 AI | 离线刷新后加载固定 BGE q8 / ONNX WASM，隐私问题返回“不会上传”相关原文；没有模拟向量或远程响应 |
| 真实 PDF | 离线导入生成的实际两页 PDF，经 PDF.js 解析，检索命中第二页，点击引用显示正确页码和高亮 |
| 下载损坏 | 独立测试服务篡改引擎资源字节，完整性校验拒绝就绪，未完成缓存被清理 |
| 缓存缺失 | 人为删除资源缓存，界面显示不完整；重新准备恢复全部资源 |
| 移除离线包 | 保留资料保存状态与 IndexedDB；不删除独立测试应用的缓存 |
| 版本更新 | 测试服务发布新版 Worker，禁止下载模型；复用旧模型完成准备，损坏的旧引擎缓存被重新下载。当前输入不丢失，新版等待旧页面关闭，重开后旧缓存被清理 |
| 等待更新时移除 | 同时停用等待中的新版和控制当前页面的旧版，移除后继续请求文件不会重新生成缓存 |
| 研究工作流 | 原 16 条浏览器流程保留，包括范围、笔记、导出、备份恢复与来源失效 |

此外保留引擎、存储和研究数据的 34 项功能检查，并核对 211 个第三方资源的固定字节。CI 先验证生成的离线清单与源码一致，再执行浏览器流程和资源检查，通过后部署完整 `dist/`。

并发测试也暴露了 Windows 本机静态服务的连接队列限制：Python 默认仅允许五个待处理连接，两个浏览器同时加载模块时出现连接拒绝。本机启动器的队列现为 128，测试使用同一启动器；另增加指定端口和安静日志选项，保留默认自动选择空闲端口的行为。

本轮没有新增生成式大语言模型、OCR 或跨设备同步，没有测量人工标注检索准确率。真实模型检查证明这条离线链路可运行，不代表模型能正确回答任何问题。
