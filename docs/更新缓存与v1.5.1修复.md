# 重复访问时，加载同一批程序文件

2026-11-06，CiteMind v1.5.1。

此前入口脚本带版本号，许多内部模块与样式使用固定 URL。浏览器可能在收到新首页后，继续使用尚未过期的旧模块；新功能便可能延迟出现。这个问题影响普通在线访问，完整离线包仍有独立的版本缓存和完整性校验。

## 修复

构建脚本根据顶层 JavaScript 与 CSS 的实际内容计算统一指纹，为入口、所有应用模块及样式写入版本和指纹查询参数。浏览器用生成的原生 import map 解析模块，覆盖静态及动态导入；Node 测试保留规范模块路径，避免同一引擎出现两个实例。

参考 [MDN import map 文档](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script/type/importmap)。映射在模块加载前声明，不依赖外部服务。模型的独立 Worker 使用自身模块 URL，因此保留相同指纹；第三方组件继续使用已有固定版本和模型修订路径。

这一步整合进 `npm run build:offline`。修改模块或样式后，即使没有更改版本号，指纹也会变化。`npm run verify:offline` 会检查首页映射及完整离线清单；漏掉生成步骤时 CI 拒绝发布。

## 实际验证

独立测试站点先将两个旧资源写入浏览器 HTTP 缓存：一个加载即报错的研究模块，以及让整个页面隐藏的旧样式。随后打开当前首页，确认输入框可见且可用、证据地图能打开、没有页面异常，并核对应用模块与样式请求使用同一版本和内容指纹。桌面与移动布局各执行一次。

另在独立临时项目中执行真实构建：不改变版本号，分别修改模块和样式，确认指纹变化；过期输出检查失败，无修改构建可复现，第三方二进制字节保持一致。

另模拟了已有可用离线包后的新版下载损坏：新版资源声明与实际响应不符，安装失败，原缓存和激活版本保留；当前草稿不丢失，断网刷新后仍可检索。桌面与移动布局均通过。

真实模型、PDF 动态导入和断网重开的既有流程继续执行，核对版本映射没有破坏离线加载。当前共 39 项功能检查与 46 条浏览器用例，其中真实模型推理仅桌面执行，合计 45 通过、1 跳过。

查询参数用于避开旧资源缓存，不保留服务器上的历史文件副本；它不是完整在线发布事务。首页本身仍受托管服务和浏览器缓存策略影响。已准备的离线包继续使用原先“完整下载校验、新版等待旧页面关闭”的生命周期。
