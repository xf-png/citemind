# Word 导入与 v1.6 实现

本轮把实际资料入口扩展到 Word DOCX：提取文字后继续使用已有的检索、原文定位、证据笔记、地图和 JSON 备份。所有读取在浏览器内完成，原始 Word 不上传、不写入知识库备份。

## 高星项目参考

2026-11-06 阅读以下项目的公开说明与实现，星数为当日页面的约数，会变化。

| 来源 | 学到的处理方式 | 本项目的取舍 |
| --- | --- | --- |
| [microsoft/markitdown](https://github.com/microsoft/markitdown)，约 194.1k 星；[DOCX 转换器](https://github.com/microsoft/markitdown/blob/main/packages/markitdown/src/markitdown/converters/_docx_converter.py) | 各格式独立转换，先处理文档结构，再交给后续文本用途 | Word 按需加载独立模块，转为现有检索接口可直接接收的文字 |
| [mwilliamson/mammoth.js](https://github.com/mwilliamson/mammoth.js) | 区分 HTML 转换与纯文本提取；明确不可信文档转 HTML 的边界 | 只提取文字，显示继续使用文本节点；不生成可执行 HTML，也不读取外链目标 |

本轮没有复制这两个项目的代码，也没有引入它们的运行依赖。根据标准独立实现了有限范围的 ZIP / Word XML 读取；它不具备完整 Office 转换器的兼容范围。既有第三方资源和许可证保持原有清单。

格式与平台依据：[Microsoft WordprocessingML 结构](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document)、[PKWARE ZIP APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)、[DecompressionStream 参数](https://developer.mozilla.org/en-US/docs/Web/API/DecompressionStream/DecompressionStream)。浏览器需支持原生 `deflate-raw` 解压；不支持时会提示更新浏览器。

## 可以怎样使用

1. 拖入标准、未加密的 `.docx`，或在“选择文件”中选中它。
2. 选择参与检索的资料，针对正文、表格或脚注中的事实提问。
3. 点击引用，核对提取文字中的高亮位置；可收集证据、写批注和导出研究记录。
4. 需要下次继续时，开启本机保存或导出 JSON；需要断网重开时，先准备完整离线包并确认就绪。

表格以单元格之间的制表符、行之间的换行表示。脚注和尾注按引用顺序添加文字标签，并在正文之后附内容。Word 引用保留提取文字的 UTF-16 位置；不根据分页符或段落数编造物理页码。

## 明确的范围

- 单份最多 10 MB，最多 2,048 个 ZIP 条目，所有条目的声明展开量合计最多 64 MB；实际读取的正文 XML 最多 4 MB，脚注 / 尾注每部分最多 1 MB。
- 提取后的资料最多 100,000 个 UTF-16 单元，继续受全库 20 份、250,000 字符的限制。
- 支持 ZIP Stored / DEFLATE，验证已读取部分的长度和 CRC-32；拒绝重复或危险路径、明显重叠记录、加密、多卷及 ZIP64。不会向文件系统解压。
- 支持常用 Transitional 和 Strict Word XML 命名空间、正文关联定位、段落、表格、换行、制表符以及引用的脚注 / 尾注。
- 不支持旧 `.doc`、宏文档和模板。图片及扫描文字没有 OCR；不提取页眉页脚、批注、嵌入文件，不重现列表编号、样式、合并单元格或完整原版式。
- 跳过明确标记为删除、移出或运行级隐藏的文字，保留插入修订。样式继承、域计算、复杂替代内容或排版顺序并未完整实现，结果需要与原文件核对。
- 检测到隐藏文字或 `altChunk` 嵌入内容时给出提示。拒绝带 DTD / 实体声明的 XML；超深结构、文字超量、损坏或关联缺失返回可读错误。
- 可取消文件读取和异步解压，有 30 秒超时；同步 XML 解析期间浏览器不能即时处理取消事件，输入大小和深度另有上限。
- 同一批文件全部成功后才加入知识库；失败或取消不会留下半批资料。原始 Word 不保存在 IndexedDB，提取文字使用原有纯文本备份结构。

## 验证方式

ZIP 读取新增 5 项检查，用 Node 原生压缩和 CRC-32 生成独立参照，覆盖 Stored、DEFLATE、数据描述符、损坏校验、重复路径、加密、ZIP64、声明总量、伪造展开长度以及取消。

浏览器新增 6 条场景，分别运行桌面 1440px 和移动布局 390px，共 12 条：

- 真实 ZIP DOCX 的表格、脚注 → 检索 → 高亮原文 → 研究批注 → JSON 导出恢复，无虚构页码。
- Strict XML、自定义正文路径、修订、隐藏文字、外链和类似 HTML 的文字按预期处理，外链目标无请求。
- 损坏、空内容、超长文字、实体声明和同批 UTF-8 错误保持原库完整。
- 文件读取尚未完成及读取前的取消均能结束操作。
- 用 `python-docx 1.2.0` 生成的独立兼容样例可提取正文、表格；页眉页脚不会混入。样例与可选再生成脚本随测试提交，Python 库不是运行依赖。
- 准备完整离线包后真正关闭网络，重载页面，导入 Word、检索、写批注，再次重载恢复批注并打开原文高亮。

这些检查证明指定样例的功能链路；不代表全部 Word 文件、所有浏览器或真实手机兼容性，也不构成检索准确率评估。全套验证继续包含真实 BGE 推理和实际两页 PDF 的离线流程。

本地完整结果：44 项功能检查通过；58 条浏览器用例中 57 条通过，1 条跳过（真实模型只在桌面执行一次）；211 项第三方资源 SHA-256 校验通过；262 项离线资源与生成清单一致。桌面与移动布局均已目视检查，手机视口没有横向溢出。

公开网站另外通过 36 条桌面 / 移动布局核心流程，以及桌面上从公开站点准备离线包、断网重载、实际 Word 导入、检索与笔记恢复的完整链路。首次下载在 90 秒检查上限时尚差一个文件，分开复测后 93 秒完成；没有改动产品下载行为。[精确版本与发布记录](verification/release-v1.6.0-2026-11-06.json)。
